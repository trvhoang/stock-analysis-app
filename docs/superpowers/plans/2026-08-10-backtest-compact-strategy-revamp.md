# Backtest Compact Strategy Revamp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 270-combination Backtest search with three fixed, causal, long-only strategies; audit a frozen database-only ticker universe; execute each real trade once; and certify each ticker independently using truthful statistics.

**Architecture:** A read-only audit selects eight clean tickers before strategy evidence is examined. The indicator adapter adds a causal Backtest-only Williams Alligator label. Compact strategy definitions replace subset/grid generation, and the execution layer produces one native-timeframe trade sequence per strategy instead of overlapping-window duplicates. Validation consumes those unique events; calibration/holdout windows become reporting-only partitions. A read-only diagnostic report supplies reproducible multi-ticker evidence without submitting jobs or overwriting current artifacts.

**Tech Stack:** Python 3.12, pandas, NumPy, SQLAlchemy/PostgreSQL, existing Backtest engine tests, Docker test environment.

- The audit uses the current database's shared available date bounds when a

  warning; Backtest derives `high=max(high, open, close)` and
  `low=min(low, open, close)` in memory only. A mismatch `>1%` remains
  audit-invalid. `validate_ohlcv()` keeps callers structurally safe without
  repairing raw database values; an invalid or indeterminate audit carries a

1. VCB is indeterminate in the required database-only audit, so the fixed-canary rule conflicts with clean-universe selection.
